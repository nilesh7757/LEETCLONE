# API Specification & Design Document - LogiQuest

## 1. Introduction
This document details the REST API endpoints and WebSocket event specifications for LogiQuest. The API follows a strict JSON structure, utilizes standard HTTP status codes, and enforces stateless authentication via JWT tokens.

## 2. API Global Standards

### 2.1 Authentication & Authorization
All secured endpoints require an `Authorization: Bearer <token>` header containing a NextAuth-signed JWT.
- **Roles:** Verified through the JWT payload (e.g., `role: "ADMIN"` or `"USER"`).

### 2.2 Standard Error Response
```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "You have exceeded the maximum of 10 requests per minute.",
    "details": null
  }
}
```

## 3. REST Endpoints

### 3.1 Problem Domain
#### `GET /api/v1/problems`
Fetches a paginated, filterable list of problems.
- **Query Params:**
  - `page` (int, default: 1)
  - `limit` (int, max: 50)
  - `difficulty` (EASY | MEDIUM | HARD)
  - `tags` (string, comma-separated e.g., `dp,graphs`)
- **Response (200 OK):**
```json
{
  "success": true,
  "data": [
    {
      "id": "uuid-1234",
      "title": "Two Sum",
      "difficulty": "EASY",
      "acceptanceRate": 45.2
    }
  ],
  "meta": { "totalCount": 1420, "page": 1, "totalPages": 29 }
}
```

#### `GET /api/v1/problems/:id`
Retrieves detailed problem metadata including code templates.
- **Response (200 OK):** Problem entity with markdown description, base boilerplate code for all languages, constraints, and visible test cases.

### 3.2 Submission Domain
#### `POST /api/v1/submissions`
Submits code for evaluation against a problem.
- **Rate Limit:** 10 submissions / min / user.
- **Payload:**
```json
{
  "problemId": "uuid-1234",
  "languageId": 71, // Judge0 ID for Python 3.11
  "sourceCode": "def twoSum(nums, target):\n    return []"
}
```
- **Response (201 Created):**
```json
{
  "success": true,
  "data": {
    "submissionId": "sub-9876",
    "status": "PENDING"
  }
}
```

#### `POST /api/v1/webhooks/judge0`
(Internal) Consumes Judge0 execution results.
- **Security:** Verified via `X-Judge0-Token` header.
- **Payload:** Array of Judge0 execution objects.

### 3.3 AI & Analytics Domain
#### `POST /api/v1/ai/audit`
Requests an AST parsing and algorithmic audit of a completed submission.
- **Payload:** `{ "submissionId": "sub-9876" }`
- **Response (200 OK):** Streams text (Server-Sent Events) containing time complexity analysis and refactoring suggestions generated by Gemini/Groq.

## 4. WebSocket (Socket.IO) Protocol

### 4.1 Connection & Auth
- **Endpoint:** `wss://ws.logiquest.com/`
- **Handshake:** Validates JWT in `auth.token`. Disconnects if invalid.

### 4.2 Namespace: `/collaboration`
- **Client Emits:**
  - `join_room({ roomId })`: Subscribes the socket to a specific room.
  - `code_delta({ roomId, changes })`: Broadcasts Monaco editor OT operations.
  - `cursor_move({ roomId, position })`: Broadcasts cursor line/column to render peer cursors.
- **Server Emits:**
  - `user_joined({ user })`: Acknowledges a new peer.
  - `code_delta_update(changes)`: Relays code changes to peers.
  - `submission_update(status)`: Pushes realtime status updates (e.g. `PROCESSING` -> `ACCEPTED`) triggered by Redis Pub/Sub from the Webhook.
